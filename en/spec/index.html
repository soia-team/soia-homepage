Move a task from something done once to work a team can use repeatedly.

This specification defines how SOIA grows a Skill into a Workflow, Plugin, Expert, custom Expert, and eventually a private registry. It does not present unreleased capability as a finished product.

PRODUCT GOALDiscoverable, installable, acceptable
PUBLIC INPUTPublic Skills and documentation evidence
PRIVATE INPUTAuthorised SOP and material
HOSTSClaude Code / Codex / WorkBuddy
RELEASE RULEEvidence before claims

Problem

People do not need more tool names. They need capability that can be found, run, checked, maintained, and handed to someone else.

When context, steps, tools, and acceptance conditions live only in chat history, every run begins from zero. A team cannot tell what is safe to publish, what needs authorisation, or how to hand over a result that merely “looks done.”

“We do not treat AI as one answer. We treat it as a work path with input, boundary, and receipt.”

Product rules

Every delivery shape must meet these four checkable rules.

01 / SOURCE

Facts have a source

Public pages link to repositories, canonical documentation, and version evidence; uncertainty is marked Preview or Roadmap.

02 / HOST

Name the host

Claude Code, Codex, and WorkBuddy are distinct environments. Capability, model, and host are not conflated.

03 / CONTROL

People retain key decisions

Publishing, payment, deletion, permission, and external writes need explicit authorisation; preview first whenever possible.

04 / RECEIPT

Delivery is reviewable

Outcomes include artifacts, checks, limits, and next actions so maintenance and handoff do not depend on guesswork.

Construction order

This is not a date promise. It is a product path for reducing uncertainty.

01 / OPEN

Open first

Use real public Skills to validate the directory, installation, evidence, and safety boundary.

02 / PRODUCT

Then productise

Turn Workflows, Plugins, and Experts into delivery shapes and specs people can understand.

03 / PRIVATE

Land by scope last

Connect material to a private workflow only after authorisation, using a pilot and acceptance for delivery.

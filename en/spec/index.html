Let a task

This public specification explains how SOIA layers Skills into Workflows, Plugins, and Experts, and clearly labels what is Available, Preview, Service, or Roadmap.

PUBLIC SPEC

01 / Goal02 / Delivery shapes03 / Product rules04 / Build order

01 / PRODUCT GOAL

Discoverable, installable, and reviewable.

SOIA treats AI not as a single answer but as a working path with inputs, boundaries, and a receipt. Product information should make both capability and limitation clear.

PUBLIC INPUT

Public Skills, documentation, and version evidence.

PRIVATE INPUT

Approved SOPs, templates, and team materials.

02 / DELIVERY SHAPES

Be clear about what is delivered.

SkillA focused, triggerable repeatable task capability · Available↗Workflow / Plugin / ExpertConnection, installation, and role entry · Preview↗Custom ExpertA private composition of approved material and team rules · Service↗Private Plugin RegistryInternal catalog, permissions, and versions · Roadmap↗

Facts have sourcesPublic pages link to repositories, documentation, and state evidence01Hosts are explicitClaude Code, Codex, and WorkBuddy are never conflated02Critical decisions stay humanPermissions, external writes, and high-risk actions need clear approval03Delivery can be reviewedOutcomes include artifacts, checks, limitations, and next steps04

04 / BUILD ORDER

Open first, then productize, then deliver in scope.

This is not a timing commitment. It lowers uncertainty: first validate catalog, installation, evidence, and safety boundaries with real public Skills; then make Workflows, Plugins, and Experts understandable products; finally bring approved material into a scoped private workflow.

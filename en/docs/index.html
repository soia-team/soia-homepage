Start with one public Skill.

SOIA does not ask you to memorise a catalogue. Name the result you want to repeat, find the smallest public capability, and complete one checkable run in one host.

01. Pick a low-risk task first

Prefer work with a clear input, visible output, and reversible failure: archive a public page, organise material you are authorised to use, or create a draft that still needs human approval. Do not start from payment, deletion, permission changes, or live client data.

  1. Write “what result do I need?” rather than a tool name.
  2. Find a domain and minimum Skill in the open ecosystem.
  3. Open the detail page and read its input, output, boundary, and public evidence.

02. Know what it will deliver

Every public Skill should make its starting point, processing scope, and receipt legible. A public Skill instruction does not make your material public; provide only input you are authorised to process.

INPUT

An authorised start

A file, URL, repository, workspace, or clear outcome goal.

PROCESS

Bounded execution

The smallest reliable steps, with previews and approval as risk rises.

OUTPUT

A visible result

A file, draft, structured material, or action recommendation—not a vague status.

RECEIPT

A handoff you can review

Artifacts, checks, limits, blockers, and next actions stated clearly.

03. Choose one host and install

Start in the environment you already use. Claude Code, Codex, and WorkBuddy are hosts or Agent environments, not models; there is no need to configure all three on day one.

# Claude Code: add the public marketplace, then install a domain plugin
claude plugin marketplace add soia-team/soia-open-skills
claude plugin install soia-meta@soia

# Codex: add the public marketplace, then enable a domain plugin
codex plugin marketplace add soia-team/soia-open-skills
codex plugin add soia-meta@soia

After installation, run one low-risk task. Marketplace packages can temporarily lag public documentation during a release; use the public marketplace manifest and repository version when exact versioning matters.

04. Keep open capability and private delivery apart

SOIA has four distinct layers: public entry, open ecosystem, capability domain, and delivery shape. This keeps “what is free and usable” separate from “what needs authorisation.”

L1 · SOIA

Public entry

Products, pricing, docs, and navigation help select a next step.

L2 · OPEN

Open ecosystem

Generic Skills, public repos, licenses, manifests, and version evidence.

L3 · DOMAIN

Capability domain

Knowledge, content, engineering, environment, design, and other real work groups.

L4 · DELIVERY

Delivery shape

Skill, Workflow, Plugin, Expert, or authorised private adaptation.

05. Leave evidence after every run

A handoff-ready run records input, output, file changes, checks, known limits, and next actions. Passwords, tokens, cookies, client files, and restricted business material never belong in public Issues, repositories, or example pages.

Public facts come from the SOIA open source repository ↗ and the matching canonical Skill document. If authorised material needs to enter a workflow, discuss scope with non-sensitive information in services and partnerships first.

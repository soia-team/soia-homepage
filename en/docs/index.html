This guide explains how SOIA capabilities are found, installed, composed, and accepted. It covers public capability only and never asks for passwords, tokens, cookies, or customer material.

01 · Start here02 · Install03 · Four layers04 · Evidence and handoff

01 / START

Choose by outcome, not by memory.

Enter the open ecosystem and browse by domain or task. Every Skill page shows a summary, inputs and outputs, install path, safety boundary, and public source link.

  1. Write down a repeatable outcome, not a tool name.
  2. Find the smallest useful Skill in the domain index.
  3. Read the public instructions before installing the full domain Plugin.

02 / INSTALL

Three entry points for three depths of use.

The public catalogue serves Claude Code, Codex, and WorkBuddy. Domain Plugins are the normal path; an individual Skill is useful for a quick trial.

claude plugin marketplace add soia-team/soia-open-skills
claude plugin install soia-meta@soia

codex plugin marketplace add soia-team/soia-open-skills
codex plugin add soia-meta@soia

After installation, start with a low-risk and reversible task. Publishing, payment, deletion, permission changes, and external writes retain a human approval gate.

03 / BOUNDARY

Four layers keep capability separate from material.

L1 · SOIA

Public entry

Brand, navigation, docs, and product explanation for the first step.

L2 · OPEN

Open ecosystem

Generic Skills, public Plugins, source, licenses, and version evidence.

L3 · DOMAIN

Capability domain

Knowledge, environment, engineering, content, design, office, and education catalogues.

L4 · DELIVERY

Delivery shape

Skill, Workflow, Plugin, Expert, or an authorised private adaptation.

04 / EVIDENCE

Every run should leave a handoff-ready receipt.

The GitHub repository and canonical instructions are the source of truth for public capability. A run should at least record inputs, outputs, changed files, checks, known limits, and next actions.

  • Public Skill monorepo ↗: Plugins, manifests, and index.
  • Knowledge and content repo ↗: capture, distill, and transform.
  • For private material, use services and partnerships to confirm scope; the public repository does not carry authorised material.

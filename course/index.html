THE REAL PROBLEM

会用 AI，
还不等于有工作系统。

如果结果只能留在一次聊天里，它就难以复用、交接和验收。这门课从一个真实重复任务出发，把临时经验变成可以继续维护的工作资产。

01 / CONTEXT

每次都要重新解释

背景、要求和边界散落在聊天记录里，换一个会话就从头开始。

02 / CONSISTENCY

同一任务结果不稳定

有 prompt，却没有明确输入、输出、检查点和失败处理。

03 / DELIVERY

做出 Demo，不会交付

不知道如何封装、安装、验证、更新，也无法让别人安全使用。

04 / BOUNDARY

公开与私有混在一起

通用方法、客户资料、账号凭据和内部流程没有清楚分层。

COURSE OUTCOME

结业不是“听懂了”，

课程围绕你的一个真实任务推进。每个模块都留下可检查的产物，最终组合成一套可安装、可运行、可验收的交付包。

BEFORE / AFTER

从临时对话，
变成可维护交付。

课程不追求“全自动”。先把人必须判断的位置标出来，再让 Agent 承担可以重复、可以检查的部分。

BEFORE

  • 每次重新解释上下文

  • 无法判断结果是否合格

AFTER

  • Skill 写清任务、边界与验收

FIT CHECK

适合谁，
也提前说清不适合谁。

首期会优先选择任务边界清楚、资料可合法使用、能在课程周期内完成一次验收的人。

适合

带着真实流程来的人

  • 开发者、顾问、运营或团队负责人
  • 已经有一项经常重复的工作
  • 愿意拆解流程并亲手完成项目
  • 希望把个人经验变成团队资产
不适合

只想拿万能模板的人

  • 期待一键赚钱或无人值守全自动
  • 不愿提供任何流程信息，却要求深度定制
  • 把课程当作完整代开发服务
  • 希望绕过授权使用他人数据或账号

CURRICULUM

8 个模块，
围绕一条真实主线。

模块顺序对应真实交付过程：先选对问题，再封装能力，最后完成安装、验收和维护。

模块学习与实践当堂产物
00 · 选择流程用频率、价值、风险和可验收性筛选首个 Agent 化任务，明确不做什么。Pilot Brief
01 · Skill 基础写清触发条件、输入、输出、步骤、工具、边界和验收，完成第一个可读 Skill。Skill 目录
02 · 多 Skill 工作流拆分职责、依赖、交接、人工批准点和失败处理，避免做成无法维护的大 Skill。Workflow Map
03 · Claude / Codex 插件理解域边界、manifest、安装、启停和版本，让同一核心能力进入两个插件宿主。可安装插件
04 · WorkBuddy 专家选择 Agent 或 Team，组织角色、Skills、资料、脚本、模板和推荐任务。专家包
05 · 私有交付区分公共方法与私有流程，处理 Git 权限、凭据、脱敏和客户资料边界。私有交付方案
06 · 测试与维护建立验收样例、回归检查、版本、更新、回滚和交接说明。验收维护清单
07 · 结业项目用真实输入完整运行一次，展示产物、限制、人工决策点和下一轮改进。可演示交付包

FAQ

申请前常见问题。

还有未覆盖的问题，可以在申请中只写非敏感背景；课程细节确认后会统一更新本页。

不会编程，可以申请吗？

可以申请，但需要愿意理解文件、目录、版本和测试这些基本概念。首期会根据项目难度确认是否适合；如果任务需要大量定制开发，会建议转入 Services。

Claude Code、Codex 和 WorkBuddy 都必须安装吗？

不要求一开始全部安装。你至少需要一个可运行宿主；课程会解释三者的交付差异，并根据结业目标选择插件或专家路径。

Skill 和普通 prompt 有什么区别？

prompt 通常只描述一次对话要求；Skill 还会明确触发、输入、输出、步骤、工具、限制和验收，并可以携带脚本、参考资料与模板。

我的公司资料会进入公开仓吗？

不会。课程只使用你有权使用的材料；通用方法和私有资料必须分开。涉及真实客户或公司秘密时，应使用脱敏样例或改走私有服务。

课程和定制服务有什么区别？

课程由你亲手完成自己的结业项目；定制服务由 SOIA 围绕约定流程承担分析、封装、安装、验收和交接，范围与责任单独确认。

结业后如何更新和维护？

课程会提供版本、回归、更新和回滚清单。持续代维护、宿主兼容更新或新增场景不自动包含在课程内，可另行评估。

SOIA / PUBLIC PRODUCT SPEC

让一个任务，
可以被团队反复使用。

这份公开规格说明 SOIA 如何把 Skill 逐层组合成 Workflow、Plugin 与 Expert，并清楚标注哪些是 Available、Preview、Service 或 Roadmap。

PUBLIC SPEC

01 / 目标02 / 产品形态03 / 产品规则04 / 建设顺序

01 / PRODUCT GOAL

可发现、可安装、可验收。

SOIA 不把 AI 当作一句回答，而是当作一条有输入、有边界、有回执的工作路径。产品说明让使用者知道能做什么，也知道不能做什么。

PUBLIC INPUT

公开 Skill、文档与版本证据。

PRIVATE INPUT

经授权的 SOP、模板与团队资料。

02 / DELIVERY SHAPES

交付什么，要先说清楚。

Skill职责聚焦、可触发的重复任务能力 · Available↗Workflow / Plugin / Expert连接、安装与角色入口 · Preview↗定制 Expert授权资料和团队规则的私有组合 · Service↗私有插件仓库团队内部能力目录、权限与版本 · Roadmap↗

03 / PRODUCT RULES

四条可检查的规则。

事实有来源公开页面链接到仓库、说明和状态证据01宿主说清楚Claude Code、Codex 与 WorkBuddy 不混称02关键决定留给人权限、外部写入和高风险动作需要明确授权03交付可以复核结果包含产物、检查、限制与下一步04

04 / BUILD ORDER

先公开，再产品化，最后按范围落地。

这不是时间承诺，而是降低不确定性的建设顺序：先用真实公开 Skills 验证目录、安装、证据和安全边界；再把 Workflow、Plugin 与 Expert 做成用户能理解的产品；最后才在授权范围内接入私有流程。

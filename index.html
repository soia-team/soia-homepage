WHY SOIA

AI 能回答问题，不等于它能稳定完成工作。

当背景、步骤、工具和验收只存在于聊天记录里，每次执行都像重新开始。SOIA 把这些隐性经验整理为可以安装、复跑、检查和交接的工作资产。

01 / CONTEXT

每次都要重新解释背景

个人偏好、业务约束和历史判断没有成为可复用的输入。

02 / DELIVERY

结果无法复核与交接

只有一段回答，没有固定产物、检查规则、失败处理与执行证据。

03 / PORTABILITY

一换工具，流程又从头开始

能力绑在单次 prompt 或单个平台里，经验无法在不同宿主之间迁移。

FAQ

先回答几个关键问题。

开放生态、课程和私有服务分别写在对应页面，不再混在一张产品清单里。

SOIA 与普通 prompt 有什么区别？

Prompt 往往只描述一次请求；Skill 还会定义触发条件、步骤、工具、边界、产物和验收。多个 Skill 可以进一步组成能复跑的工作流。

必须同时安装三个宿主吗？

不需要。你可以只选择 Claude Code、Codex 或 WorkBuddy 中最适合自己的一个入口。开放生态中的每个 Skill 都会标注适用宿主和安装方式。

开放生态与私有服务的边界是什么？

通用方法、Skill 和工具尽量公开；你的账号、数据、模板与专有流程保持私有。服务交付的是适配、组合、验收和维护，不会把客户资料加入开源仓库。

SOIA 会代替人自动发布或执行高风险操作吗？

不会默认这样做。公开工作流强调人工批准；发布、授权、付款和其他外部写操作必须经过用户确认。

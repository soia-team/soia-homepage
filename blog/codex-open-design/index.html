Codex × Open Design：从截图到可运行页面

Open Design 不是替代 Codex，而是把视觉参考、设计系统和预览组织成 Codex 可以持续使用的设计上下文。

2026 年 8 月 2 日 · 指南 · 8 分钟阅读

本文内容

两者怎样分工完整工作流截图怎样使用生产实现检查与交付

01 / ROLES

一个负责设计上下文，一个负责把结果落进仓库。

Open Design 是本地设计工作区：它把截图、视觉方向、Design System 和预览放在同一条设计会话中。Codex 是执行者：它读取项目规则、理解现有代码、实现页面、运行检查，并根据浏览器结果继续修正。

最重要的判断：Open Design 产出的原型是视觉依据，不自动等于生产代码。生产站仍要遵守仓库结构、可访问性、响应式、内容边界和发布检查。

02 / WORKFLOW

从参考到交付，一共六步。

  1. 准备真实截图、目标页面、品牌内容与仓库规则。
  2. 在 Open Design 中生成可比较的页面骨架和设计语言。
  3. 确定字体、颜色、间距、组件和导航交互。
  4. 由 Codex 把合格方向写入共享 CSS、JS 和语义 HTML。
  5. 在桌面、移动端和键盘路径下检查页面与下拉交互。
  6. 运行站点验证，确认链接、canonical、语言页与公开边界后发布。

03 / SCREENSHOT TO STRUCTURE

截图不是让 Agent 描像素，而是补齐结构证据。

首页截图告诉我们导航、首屏比例和视觉重心；价格页截图说明套餐密度、强调层和按钮节奏；技能目录与详情截图定义二级、三级页面的层级；博客列表与文章截图补齐内容系统。

每张截图都应同时附上“保留什么、替换什么、不能复制什么”。这样得到的是可迁移的设计语言，而不是带着第三方品牌和文案的镜像。

04 / PRODUCTION CODE

共享组件优先，页面内容随后填入。

头部、mega menu、按钮、卡片、详情侧栏和文章目录应该由一套共享样式和脚本管理。SOIA 的页面内容再映射进去：开放生态使用能力目录，技能详情展示使用场景与公开证据，博客解释方法和案例，价格页说明免费能力、课程与私有服务的边界。

Codex 在这里承担的工作

识别重复结构、控制改动范围、保留既有路由和 SEO 元数据、补齐中英文页面，并把每个视觉判断转成可被测试的 DOM、CSS 和交互行为。

05 / CHECKS

视觉接近只是第一层，真正完成还需要证据。

  • 桌面与移动端没有横向溢出。
  • mega menu 可由鼠标、键盘和移动端按钮操作。
  • 每个页面只有一个主标题和一个 main landmark。
  • 内部链接、语言切换、canonical 与 sitemap 对应真实页面。
  • 没有第三方品牌、文案、截图、追踪代码或未授权素材残留。

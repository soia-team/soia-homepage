从一个公开 Skill 开始。

SOIA 不是让你先背完整技能目录。先写下你希望重复完成的结果，找到最小的公开能力，在一个宿主里完成一次可检查的运行。

01. 先选一个低风险任务

优先选择输入清楚、输出可见、失败可撤回的任务，例如归档一篇公开网页、整理一份自己有权使用的资料，或生成一份需要人工确认的发布草稿。不要从付款、删除、权限变更或真实客户数据开始。

  1. 写“我要得到什么结果”，不是“我要用哪个工具”。
  2. 用结果关键词在开放生态里找到一个能力域与最小 Skill。
  3. 打开详情页，先读输入、输出、边界与公开证据。

02. 看清它会交付什么

每个公开 Skill 都应清楚说明它的起点、处理范围和回执。Skill 的说明公开，不等于你的资料要公开；使用时只给出你有权处理的输入。

INPUT

有权使用的起点

文件、URL、仓库、工作区或一个明确结果目标。

PROCESS

受限的执行

最小可靠步骤，风险上升处保留预览与批准。

OUTPUT

可见的结果

文件、草稿、结构化资料或操作建议，而不是模糊状态。

RECEIPT

可以交接的回执

产物、检查、限制、阻塞和下一步都说清楚。

03. 选择一个宿主并安装

先选择你正在使用的一个工作环境。Claude Code、Codex 和 WorkBuddy 是宿主或 Agent 环境，不是模型；没有必要一开始把三个环境全部安装并配置。

# Claude Code：添加公开市场，再安装一个领域插件
claude plugin marketplace add soia-team/soia-open-skills
claude plugin install soia-meta@soia

# Codex：添加公开市场，再启用一个领域插件
codex plugin marketplace add soia-team/soia-open-skills
codex plugin add soia-meta@soia

安装之后，先运行一个低风险任务。插件市场的可安装版本可能在发布中暂时落后公开文档；需要精确版本时，以公开 marketplace manifest 和仓库版本为准。

04. 把公开能力和私有交付分开

SOIA 的公共入口、开放生态、能力域与交付形态是四个不同层次。这样“免费能用什么”和“需要授权才能做什么”不会混淆。

L1 · SOIA

公共入口

产品、价格、文档和导航，帮助你选择下一步。

L2 · OPEN

开放生态

通用 Skill、公开仓、许可证、manifest 与版本证据。

L3 · DOMAIN

能力域

按知识、内容、工程、环境、设计等真实任务分组。

L4 · DELIVERY

交付形态

Skill、Workflow、Plugin、Expert 或授权范围内的私有适配。

05. 每一次运行留下证据

一次可交接的运行至少写清输入、输出、文件变化、检查、已知限制和下一步。密码、Token、Cookie、客户文件以及受限制的业务资料不应放进公开 Issue、公共仓库或示例页面。

公共事实以SOIA 开源总仓 ↗与对应 Skill 的规范文档为准。需要把授权资料接入流程时，先在服务与合作中用非敏感信息讨论范围。

# SOIA Public Web · Open Design review receipt

Date: 2026-08-02
Scope: public homepage, bilingual top-level routes, capability domains, and individual Skill pages

## Outcome

The public site now follows the SOIA visual direction used in Open Design: a warm technical canvas, dark evidence panels, restrained orange emphasis, and a typography system that separates reading, display, and machine-readable labels.

This review does not certify a complete formal Open Design package. The selected `Soia` design system currently provides the legacy `DESIGN.md`; a complete reusable package should also add `manifest.json` and `tokens.css` in a SOIA-owned repository before being imported into Open Design.

## Decisions applied

- Body and interface copy use self-hosted Public Sans with system CJK fallbacks.
- Display headings use self-hosted Space Grotesk with weights capped at the bundled font range.
- Labels, route levels, snapshots, and code use self-hosted JetBrains Mono.
- The palette is based on warm paper, ink, espresso, controlled orange, and a restrained evidence blue.
- Blue is limited to brand and evidence/status roles; interactive emphasis and focus return to the orange control accent.
- Chinese and English pages share one component and spacing system instead of separate visual themes.
- Capability information is explicit at four levels: SOIA → Open → capability domain → Skill.
- The Kanvis-inspired page system is expressed as three SOIA-owned Open views: Open home (`?tab=home`), Skills catalogue (`?tab=skill`), and Workbench / Experts (`?tab=workbench`). The information hierarchy is retained; all copy, examples, links, and visual assets are SOIA-owned.
- The featured Skill index exposes 16 entries with All / Skill / Workflow / Plugin / Expert filters before the eight canonical capability domains.
- Status and evidence are kept separate from marketing copy; catalog documentation is not presented as proof that every marketplace release is already installable.

## Published information architecture

- 6 Chinese top-level routes
- 6 English top-level routes
- 8 capability-domain pages in each language
- 79 individual Skill pages in each language
- 186 routed pages in total

The generated pages use a public catalog snapshot and expose its source commit and date. Each Skill page includes a breadcrumb, route level, public summary, delivery contract, installation choices, safety boundary, and evidence links.

## Review findings resolved

The read-only review completed inside the updated Open Design workspace with the `Soia` design system selected. It found no release-blocking P0 issue. Its three highest-priority findings were resolved before publication:

- English parity: the English homepage and Open page now contain the same decision-making layers as the Chinese site, and all 79 English Skill summaries are individually derived from the public catalog instead of a generic template.
- Accent discipline: orange is the control and interaction accent; blue is limited to brand and evidence/status roles.
- Mobile density: 44-pixel controls, card-based table rows, wrapped install commands, and a real 390-pixel CSS viewport check replace desktop-only shrinking.

## Verification

Run from the repository root:

```bash
pnpm test
```

Current result:

```text
[OK] validated 186 routed pages, 404, shared assets, 1542 links, robots.txt and sitemap.xml
```

Browser review covered the Chinese and English Open views, the featured Skill index and filter interaction, a capability-domain page, and an individual Skill page. The language switch, shared navigation, three-view Open routing, hierarchy, typography, and evidence panels were checked against the rendered pages. The local browser console reported no errors. The formal Open Design CLI check remains environment-pending because the available Node / pnpm versions differ from the package's expected versions; the published SOIA design-system catalog and daemon were available and used as design input.

The public site is intentionally light-only for this release: the warm paper canvas and dark evidence panels are part of one editorial composition, not an operating-system theme. A future dark theme should be designed as a complete token set instead of generated by automatic color inversion.
